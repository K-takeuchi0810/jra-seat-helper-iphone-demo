# 席取りサポート — iPhone用クラウド版（開発版）

iPhoneから希望席の設定、開始・中止、ブラウザ操作と状況確認を行う個人用アプリです。iOS 16.4以降のSafariでホーム画面に追加すると、Web Push通知を登録できます。待機処理をiPhoneの画面内で実行する構成ではないため、利用者のWindows PCは必要ありません。

**2026年11月18日、利用者による実購入の完了を確認しました。** Render上の通常表示ブラウザを使った構成で、JRAの「購入完了」「お手続きが完了しました」の画像が提供され、利用者から別のローカルブラウザの購入履歴でも確認済みと報告されています。Render上のブラウザ起動とiPhoneへの通知到着も確認済みです。今回の1件での検証であり、すべてのカード・環境での決済や無料クラウドの長時間継続稼働を保証するものではありません。

## 開催と希望条件の事前設定

1. ブラウザを開き、JRAへログインします。ホームの「開催一覧を取得」で、サイトで現在選択できる開催競馬場と開催日を読み込みます。
2. 競馬場・開催日を選ぶと、その条件でサイトを検索して席種を取得します。追加操作やログインが必要な画面では停止し、その画面を維持します。
3. 席種・枚数・エリアを指定します。満席も「現在満席・キャンセル待ち」と表示し、定期確認をオンにして希望に登録できます。一覧から消すのではなく、申し込み可能な状態に変わるまで待ちます。
4. 条件は端末に保存・復元できます。ログイン情報・認証コードは含まず、開始日時と自動開始は復元しません。「今すぐ」または24時間以内の「日時を指定」を選べます。実行中は条件を変更できず、実際の実行条件を別に表示します。
5. 開始前、一覧更新後、申し込み直前に、画面の競馬場・開催日と指定条件を照合します。希望枚数の申し込み後に決済画面を検出して通知し、自動操作を終了します。確保不可・不明・混雑を成功扱いしません。

席種一覧は取得時点の情報です。発売前の開催、満席、受付停止は異なり、カレンダーに日付があるだけでは購入可能とは判定しません。定期確認は10秒以上、処理は直列で行います。申し込み中はブラウザの画面転送を抑えますが、秒単位の確保を保証する機能ではありません。

## できること

- 希望席を第3希望まで設定し、枚数・エリア・日本時間の開始日時を指定。
- 申し込み前の一覧で空き表示がなければ、10秒以上の間隔で最大120分間確認。
- iPhoneの画面から、クラウド側のブラウザをタップ・文字入力・スクロール操作。
- 席種の注意事項チェック・次へ進む・希望枚数の選択を自動化。ログイン、未対応の追加確認、購入確定は本人が操作。
- 支払い画面の検出、本人の操作待ち、処理停止の際にプッシュ通知を送信。
- 通知が送信できなくても、申し込み処理の状態表示を保持。

「○・△」は申し込み候補で、確保の保証ではありません。「確保できるまで定期確認」をオンにした場合、サイトが「ご希望の条件にて、お席をご用意することができませんでした。」と明確に回答したときだけ、設定した間隔（10秒以上）を空けて同じ枚数・エリアで再確認します。失敗した送信の再読み込みは行わず、確認済みの席種一覧へGETで戻ります。監視時間は最大120分で、確保後・結果不明・追加確認・支払い画面を検出した場合は再申し込みしません。席種に紐づく「注意事項を確認しました」「次へ進む」は自動操作します。未対応の確認画面では停止します。定期確認がオフなら確保不可で停止します。

支払い画面の検出通知は「購入手続きの確認待ち」です。確保の成立、取り置き期限、購入完了を保証するものではありません。購入確定は自動化していません。

## 無料運用に関する未解決事項

同梱の`render.yaml`は、**Free Web Service・デモモードのみ**の設定です。有料プラン、Background Worker、Cron Job、データベース、永続ディスクは定義していません。

Render無料Webサービスは受信アクセスが15分ないと停止します。iPhoneを閉じた後の長時間監視は保証できず、サーバーが停止・再起動すると動作中のブラウザと待機ジョブは失われます。本実装はそれを成功と見せかけたり、再起動後に申し込みを勝手に再送したりしません。

したがって、無料Renderへの公開だけでは「iPhoneを閉じて長時間待ち、確保時に通知」という要件を満たしたとは判定できません。対策候補として、`monitor/`にGoogle Apps Scriptによる5分ごとの公開ヘルスチェックを用意しました。スマートフォンを閉じている間もサーバーへの外部リクエストを継続する構成ですが、利用者の実行ログでHTTP 200を確認しています。ただし、単発のヘルスチェックは長時間の継続動作の証明ではありません。

Freeプランでも、支払方法を登録済みのアカウントでは、帯域やビルドの無料枠超過分が請求される場合があります。0円の条件を確認するまでは公開しません。支払方法の追加・有料アップグレードは不要であり、本アプリの設定や起動で行うものではありません。

## iPhoneでの利用手順（公開後）

1. Safariで専用のHTTPS URLを開き、このアプリ専用のログイン鍵を入力します。JRAの認証情報とは別の鍵です。
2. Safariの共有メニューから「ホーム画面に追加」を選び、追加したアイコンから開き直します。
3. 「通知」で通知を許可し、テストを送信します。ロック画面などに実際に届いてから「届きました」を押します。サーバーの送信受付だけでは到着確認とは扱いません。
4. 「ホーム」からブラウザを開き、「ブラウザ」でJRAにログインして開催日・競馬場を選び、席種一覧へ進みます。
5. 席種を読み込み、希望条件と開始日時を設定します。開始前の確認画面で開催日・競馬場を確認します。
6. 追加確認の通知が届いたら、「ブラウザ」で内容を読み、本人が操作します。
7. 支払い画面に進んだ通知が届いたら、このアプリのブラウザで成立状況・期限・金額などを確認します。購入する場合は本人が確定します。

アプリの「中止」は今後の操作を止めるもので、送信済みの申し込みを取り消す機能ではありません。アプリからログアウトしても、動作中のジョブとブラウザは終了しません。必要に応じて中止とブラウザ終了を行ってください。

## データとログイン

ブラウザのログイン状態と入力文字はクラウド上で扱います。自分のクラウドアカウントで動かすことを想定しています。JRAの認証情報を設定ファイルやアプリのログへ保存する処理はありませんが、クラウド事業者を使うこと自体はクラウドを信頼する選択を伴います。

- アプリの操作画面・ブラウザ画像・APIはログインで保護します。
- 認証CookieはHttpOnly・SameSite=Strict。本番ではSecureを付けます。ログアウト後はコピー済みCookieも無効化します。
- ブラウザ画像、JRAのURL、入力文字をアプリの履歴ファイルへ保存しません。
- 通知先の購読情報は`APP_DATA_DIR`のJSONファイルに保存します。JRAの認証情報は含みません。
- プッシュ通知には固定の進行メッセージのみを載せ、会員番号、パスワード、席名、決済情報や画面画像を含めません。
- Renderの無料領域は再起動時に消えるため、通知登録を再送する必要がある場合があります。
- 待機列・混雑・追加認証を検出した際の回避処理はありません。JRAの利用条件に適合する許可がある範囲でのみ使用してください。

## 開発・ローカル検証

Python 3.11以降、Node.js、Google Chrome、または対応するChromiumが必要です。依存関係をインストールします。

```text
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
npm ci --ignore-scripts
```

Windowsでは、PowerShellで環境変数を設定して起動できます。ログイン鍵は専用のランダム値を使用し、JRAのパスワードは設定しません。

```powershell
$env:APP_LOGIN_SECRET='<32文字以上の専用ランダム値>'
$env:SECURE_COOKIES='0'
$env:DEMO_ONLY='1'
$env:HOST='127.0.0.1'
$env:PORT='8080'
.\.venv\Scripts\python.exe server.py
```

ローカルHTTPで実機へのWeb Push登録を行うことはできません。公開時はHTTPSと`SECURE_COOKIES=1`が必要です。`DEMO_ONLY=0`で実サイトを開く設定になりますが、実サイトを対象とするクラウド版の動作は未検証です。

Linuxコンテナ用のDockerfileを同梱しています。ローカルのLinux・Docker環境で構築し、512MiB・0.1CPUの制限をかけたデモ動作を確認しました。Chromiumは非rootユーザーで起動し、`chromium-sandbox`を明示的にインストールしています。

検証環境では、Microsoftの[公式Docker手順](https://playwright.dev/docs/docker)にあるユーザー名前空間の作成を許可するseccompプロファイルが必要でした。標準Docker設定では起動に失敗します。`--no-sandbox`・`--privileged`・`seccomp=unconfined`は使用していません。ブラウザ自身の状態画面で、PID・ネットワーク名前空間とSeccomp-BPFによる隔離が有効であることを確認しました。

この検証結果は、同じプロファイルを指定できないホスティング環境での動作を保証しません。Renderで必要な条件を満たせるかは公開前の確認事項です。

## 構成

`engine.py`がブラウザ操作、`controller.py`が単一ブラウザの制御、`server.py`が認証付き操作画面とAPI、`push_service.py`と`push.mjs`がWeb Push、`static/`がiPhone用の画面、`monitor/`が別途設置する無料の外部稼働確認です。JRA非公式の独立した実装で、配布元の実行ファイルは含みません。

オリジナル実装はMITライセンスです。Selenium、web-pushその他の依存関係には各ライセンスが適用されます。

参考資料：[AppleのWeb Push説明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)、[Render無料枠](https://render.com/docs/free)、[Renderの請求に関するFAQ](https://render.com/docs/faq)。

「おまかせ席選択」の最大席数は席種ごとの申し込み上限として確認します（空席数とは区別します）。希望枚数が上限を超える場合は、定期確認がオンでも再試行せず、枚数または席種の見直しを案内して停止します。例えば2席希望で上限1席の席種を選んだ場合、1席のボタンを代わりに押すことはありません。最大席数の表示を確認できず、希望枚数のボタンも見つからない場合は、ページ変更の可能性があるため停止します。

実サイトモードの起動先は日本語のJRAログイン画面です。ブラウザ言語を日本語にし、会員番号・メールアドレス欄へフォーカスします。会員番号・パスワードの入力とログイン送信は本人が行います。アクセス集中・待機画面を検出した場合は、空席なしや確保成功とは扱わず、自動更新や再送を止めてサイトの画面を維持します。混雑が解消した後、本人が対象開催日の席種一覧へ進み、読み込み直してください。

## この端末でログインを保持

ログイン時に「この端末でログインを保持（最大30日）」を選択すると、サーバーの再起動や通常セッション期限切れ後もアプリへログインを復元できます。追加の有料サービスは利用しません。

- アプリのログイン鍵をlocalStorageやIndexedDBへ保存しません。端末内で生成した、Web Cryptoで取り出し不可とした署名鍵だけをIndexedDBへ保存します。
- サーバーが署名した公開鍵証明をHttpOnly・Secure・SameSite=StrictのCookieとして保存し、ログイン復元時は一度限りのチャレンジへの署名を検証します。Cookieだけのコピーではログインを復元できません。
- ログアウトすると端末の署名鍵と保持Cookieを削除し、現在のセッションを無効にします。
- 期限切れ、端末のサイトデータ削除、ブラウザの保存制限、アプリのログイン鍵の変更時は、保存済みパスワードからログインし直してください。
- JRAのログイン状態や、サーバー再起動時に失われるブラウザ・実行ジョブを復元する機能ではありません。
- 同じ端末にある許可済みのWeb Push購読も、ログイン後にサーバーへ再登録します。新しい通知権限は要求しません。

通常の空席確認は開始から次の開始までを設定間隔（初期値10秒）に近づけます。読み込みが設定間隔を超えた場合は、前の処理が終了してから次へ進み、並列確認や遅れの取り戻しのための連打はしません。明確な確保不可の回答後は、回答から設定間隔以上待ってから同じ条件で再確認します。混雑・待機・認証・結果不明では自動処理を停止します。10秒はアプリの設定値であり、JRAの公式推奨間隔として確認した値ではありません。

## JRAのID・パスワードの入力と消去

JRAのログイン画面を開くと、「JRAのログイン入力」が表示されます。iPhoneのパスワード一覧からJRAの保存項目を選び、「ログイン欄へ入力」を押すと、IDとパスワードをまとめてJRAの欄へ反映します。アプリとJRAは別のサイトのため、JRAの自動候補が出ない場合はパスワード一覧で選択してください。ログイン送信は本人が行います。

- 「JRAの両欄を空にする」で、JRA画面内のIDとパスワードをまとめて消去できます。
- 通常の入力でも「選択中の欄を空にする」で、空文字を入力できなかった問題を解消しています。入力は追記せず上書きします。
- アプリの送信受付だけで成功とは表示せず、実際の入力操作の完了を待ちます。失敗時はアプリ側の値を消さず、自動再送は行いません。
- JRAのID・パスワードはアプリの永続領域やログに保存しません。ブラウザ上のJRA入力欄へ転送し、操作完了後はアプリ側の入力欄を空にします。
- JRA用の一括入力は、JRAの正規ホストにある指定のログイン欄だけで行います。ログインを意図せず送信しないよう、改行や操作用の制御文字を拒否します。

根拠：Chrome公式 Cookie管理 https://support.google.com/chrome/answer/95647?hl=en ／ ChromeDriver一時プロファイル https://developer.chrome.com/docs/chromedriver/capabilities

## 2026-11-18 再操作レビューと満席入口への対応

操作順を、ブラウザ接続・ログイン→開催一覧取得→競馬場→開催日→希望席→枚数→開始条件→確認→開始として再検証した。

- 未準備の開催日・希望席・保存・開始ボタンを無効化し、次に必要な入力を表示する。競馬場変更時に前の希望席とエリアを消去する。
